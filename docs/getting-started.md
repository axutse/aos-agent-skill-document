# 从安装到首次交付

[简体中文](getting-started.md) | [English](getting-started.en.md)

这份教程面向第一次使用 `AOS Agent Skill · Document` 的用户。完成后，你会知道它解决什么问题、如何安装、如何选择 Skill、怎样发出一条可执行指令，以及如何验收输出。

## 1. 先理解它的定位

这是一个 **skills-only 文档出版插件**。它不提供新的聊天模型，也不把文件上传到第三方转换网站；它为 Codex 提供一套专业文档工作流，并调用本地 Python、LibreOffice 和 Poppler 完成文件处理与视觉检查。

工作流固定为：

```text
读取资料 -> 规划结构 -> 制作/修改 DOCX -> 渲染全部页面
         -> 检查并修复 -> 导出 PDF -> 再次渲染检查 -> 交付
```

“生成成功”只代表文件可以打开；“交付合格”还要求检查每页的字体、图片、表格、分页、页眉页脚、裁切、重叠和元数据。

### 适合解决

- 品牌白皮书、企业报告、年度报告、提案和方案书；
- 操作手册、制度文件、培训材料和品牌规范；
- 已有 Word 的局部修改、结构修复和公开发布清理；
- 已有 PDF 的结构检查、页面渲染、元数据清理和视觉验收；
- 同一版式下的批量文档交付。

### 不适合替代

- Word 或 Acrobat 的全部交互式编辑功能；
- 法务、财务、事实、版权或品牌授权的人工审核；
- 未提供来源时的业务数据真实性判断；
- 缺少渲染工具时的完整视觉验收。

## 2. 安装前准备

最低要求：

- 已安装并可使用 Codex；
- Python 3.10 或更高版本；
- 制作或修改 DOCX 时建议安装 LibreOffice；
- 检查 PDF 页面时建议安装 Poppler。

macOS 可使用 Homebrew 安装本地渲染工具：

```bash
brew install --cask libreoffice
brew install poppler
```

插件本身不需要 API Key。不要把密钥、客户隐私或未获授权的原始文件提交到公开仓库。

## 3. 安装插件

在终端执行：

```bash
codex plugin marketplace add axutse/aos-agent-skill-document
codex plugin add aos-agent-skill-document@aos-agent-skills
```

然后查看插件列表：

```bash
codex plugin list
```

列表中应出现 `aos-agent-skill-document`。安装或更新后，请在 Codex 中**新建一个任务**，让新的 Skill 元数据进入任务上下文。

## 4. 选择正确的 Skill

| 你的任务 | 使用的 Skill | 典型交付 |
|---|---|---|
| 从资料制作一份完整文档 | `$aos-publish-document` | DOCX + PDF + 验收结论 |
| 新建或修改 Word | `$aos-author-word` | 可编辑 DOCX，可选 PDF |
| 检查或处理 PDF | `$aos-process-pdf` | PDF + 结构/画面检查结果 |

如果你不确定，按下面的规则选择：

```text
是否需要一份从内容规划到最终交付的完整文档？
├─ 是 -> $aos-publish-document
└─ 否
   ├─ 主要操作 DOCX -> $aos-author-word
   └─ 主要操作 PDF  -> $aos-process-pdf
```

`$aos-publish-document` 是总编排入口。它会在需要时调用 Word 和 PDF 工作流，不需要用户连续手动调用三次。

## 5. 准备输入资料

建议把相关文件放在同一个项目目录，并在指令中说明目录位置。最低输入包括：

1. 文档目的和读者；
2. 原始资料文件或目录；
3. 交付格式：DOCX、PDF 或两者；
4. 语言、页数、页面尺寸、风格与截止要求；
5. 必须保留、不得改写或需要标注的内容。

可复制这个输入模板：

```text
使用 $aos-publish-document。

目标：制作【文档类型】，用于【受众/场景】。
资料：读取【文件或目录路径】中的全部相关资料。
内容：必须包含【章节/主题】，不得修改【名称/数字/术语】。
规格：【语言】、约【页数】页、【A4/Letter】、【风格描述】。
交付：需要【DOCX/PDF/两者】。
验收：逐页检查字体、图片、表格、页码、页眉页脚、裁切和重叠；
      清理个人元数据、评论、修订记录和敏感信息。
数据规则：无法验证的经营数字必须标记为“企划模拟值”，不得编造成事实。
```

## 6. 第一次完整使用：从资料制作白皮书

### 第一步：把资料放入项目

示例目录：

```text
my-white-paper/
├── source/
│   ├── 品牌介绍.docx
│   ├── 产品数据.xlsx
│   ├── 组织架构.md
│   └── images/
└── output/
```

### 第二步：向 Codex 发出任务

```text
使用 $aos-publish-document，读取 source 目录中的全部资料，制作一份面向合作伙伴的
20 页中文品牌白皮书。先给出章节与页面计划，再开始制作。整体采用简洁编辑设计，
每页只表达一个核心判断。输出到 output 目录，交付可编辑 DOCX 和对应 PDF。
保留资料中的正式名称和已验证数字，无法验证的经营数据标记为企划模拟值。
完成后渲染全部页面，逐页检查字体、图片、表格、页码、页眉页脚、裁切、重叠和
异常空白，并清理作者、评论、修订和敏感元数据。
```

### 第三步：观察执行阶段

正常流程应包含：

1. 列出已读取的资料与缺口；
2. 给出章节结构或页面蓝图；
3. 生成并结构检查 DOCX；
4. 渲染 DOCX 的全部页面并修复问题；
5. 转换 PDF，再次检查结构与全部页面；
6. 返回最终文件路径和验收摘要。

如果 Agent 只生成文件、没有渲染和检查，可以继续发出：

```text
继续执行最终验收。不要只检查文本；请渲染全部页面，在可读缩放下逐页检查，
修复后重新渲染，并报告页数、尺寸、元数据和视觉问题的最终状态。
```

## 7. 第二个完整案例：只修改现有 Word

适合已有正式模板、只允许局部改动的场景：

```text
使用 $aos-author-word 修改 report.docx，只更新第 2、5、8 节。
保留原有样式、目录、页眉页脚、章节顺序和分页，不要重做整份模板。
把修改结果保存为 output/report-public.docx，不覆盖原文件。
清理作者、评论和修订元数据；渲染全部页面，重点检查目录页码、跨页表格、图片比例、
页眉页脚和新增段落造成的分页变化。列出实际修改内容和最终验收结果。
```

关键点：明确“不覆盖原文件”“只修改哪些章节”“哪些版式必须保留”。

## 8. 第三个完整案例：先审计 PDF，不修改

适合公开发布前检查或定位问题：

```text
使用 $aos-process-pdf 检查 proposal.pdf。先不要修改文件。
检查页数、页面尺寸、旋转、加密、表单、链接、元数据和图片使用情况；
以 200 DPI 渲染全部页面，在可读缩放下检查缺字、模糊图片、裁切、重叠、
错误页框、异常空白页和表格问题。按“阻断发布 / 建议修复 / 可接受”分类输出问题清单，
并给出最小修复方案。
```

确认问题清单后，再让 Agent 修复并输出新文件，可以避免无意覆盖或扩大修改范围。

## 9. 如何验收最终交付

至少确认以下内容：

- 文件可以重新打开，DOCX 仍然可编辑；
- DOCX 与 PDF 的页数和内容符合要求；
- 所有页面都经过单页检查，不只看联系表；
- 没有文字或图片裁切、对象重叠、缺字、表格断裂或异常空白页；
- 图片没有明显拉伸或不必要的低清晰度；
- 页码、目录、页眉页脚和章节顺序正确；
- 评论、修订、作者、公司和敏感元数据符合公开策略；
- 未验证数字、占位文本和模拟数据有清楚标识；
- 最终目录只保留用户要求的交付物。

联系表适合快速浏览整体节奏，但不能替代逐页验收。

## 10. 中英文双语交付

制作中英文版本时，先说明需要两个独立文件、章节中英对照，还是同页左右对照。长文档默认推荐两个独立版本，因为中英文的换行和分页规律不同。

```text
使用 $aos-publish-document，基于同一套已验证资料分别制作简体中文版和英文版。
保持章节顺序、数字、表格、图注、页面标识和模拟值标签一致。翻译前先建立术语表；
没有正式英文名时，不要自行翻译注册名称。分别输出两种语言的 DOCX 和 PDF，
四个文件都需要独立渲染和逐页检查，并报告页数、换行和分页差异。
```

## 11. 更新与卸载

更新远程市场信息后重新安装插件：

```bash
codex plugin add aos-agent-skill-document@aos-agent-skills
```

更新完成后新建 Codex 任务再测试。卸载时执行：

```bash
codex plugin remove aos-agent-skill-document
```

## 12. 常见问题

### 安装后看不到 Skill

先运行 `codex plugin list` 确认安装状态，然后新建 Codex 任务。旧任务可能仍使用安装前的 Skill 元数据。

### DOCX 可以生成，但没有页面图片或视觉验收

确认本机安装了 LibreOffice。没有 LibreOffice 时只能完成结构检查，不能承诺完整的 Word 渲染验收。

### PDF 无法渲染

确认 `pdftoppm` 可用：

```bash
pdftoppm -v
```

若不可用，在 macOS 上运行 `brew install poppler`。

### 输出与预期不一致

补充页面尺寸、页数、读者、参考风格、必须保留内容和不得修改内容。对已有文件，明确要求“保存为新文件，不覆盖原文件”。

### 是否需要填写模型密钥

不需要。这个插件只提供工作流、参考资料和本地处理脚本，不包含外部模型路由或在线转换服务。
