# 使用案例与提示词手册

本手册提供可直接复制的文档任务写法。每条指令都明确输入、输出和验收要求，减少“帮我做得专业一点”这类不可验证描述。

## 如何选择 Skill

| 任务 | 使用 Skill |
|---|---|
| 从零规划并制作 DOCX + PDF | `$aos-publish-document` |
| 只处理 Word 或要求可编辑交付 | `$aos-author-word` |
| 只检查或处理固定版式 PDF | `$aos-process-pdf` |
| Word 修改后还要交付 PDF | 先 `$aos-author-word`，再 `$aos-process-pdf` |

## 一个完整指令应包含什么

建议依次写清：

1. 任务类型与读者；
2. 输入资料和事实来源；
3. 文档语言、页数、页面尺寸与风格；
4. 必须保留和禁止出现的内容；
5. 需要 DOCX、PDF 或两者；
6. 元数据、保密和公开范围；
7. 渲染、逐页检查和最终验收条件。

## 案例 1：品牌企业白皮书

适合企业介绍、品牌战略、商品体系和五年规划的综合发布。

```text
使用 $aos-publish-document，读取资料目录中的企业介绍、组织架构、品牌定位、
产品资料、经营规划和图片。面向合作伙伴制作一份 24 页中文品牌企业白皮书。

先输出：事实清单、模拟值清单、缺失材料、章节结构和页面预算。确认后生成可编辑
DOCX 与对应 PDF。采用结论先行的大标题、清晰表格和充分留白；每页只表达一个
核心判断。清理个人元数据，逐页检查字体、图片、表格、页码、裁切和重叠。
```

验收重点：企业与品牌关系明确；模拟值有标签；DOCX 和 PDF 页数与顺序一致。

## 案例 2：年度经营报告

适合经营复盘、指标解释、年度策略和下一年度行动计划。

```text
使用 $aos-publish-document，根据年度数据表、部门复盘和管理层结论制作年度经营报告。
不要自行补数字。所有指标必须注明期间、单位和来源；同比、环比和目标差异使用统一
口径。输出 16:9 横向 PDF 和可编辑 DOCX，包含执行摘要、核心指标、问题、原因、动作、
责任人和时间表。全部图表必须清晰标注，逐页完成渲染检查。
```

验收重点：指标口径一致；结论能追溯到数据；行动项包含责任人与时间。

## 案例 3：项目提案与解决方案

适合客户提案、内部立项和技术解决方案。

```text
使用 $aos-publish-document，把需求说明、访谈笔记和现有系统资料整理为项目提案。
结构包含背景、现状、目标、范围、方案、里程碑、角色、风险、预算假设和验收标准。
明确区分已确认需求、建议方案和待确认事项。输出可编辑 DOCX 与用于评审的 PDF，
所有表格保持可编辑，并检查长表格跨页、标题层级和页码。
```

验收重点：范围边界清楚；假设没有伪装成事实；风险和验收标准可执行。

## 案例 4：SOP、制度或员工手册

适合流程说明、岗位规范、审批制度和操作手册。

```text
使用 $aos-author-word，把现有制度、聊天记录和流程说明整理为正式 SOP。使用编号标题、
角色职责、前置条件、操作步骤、异常处理、审批节点、记录留存和版本信息。保留所有
已验证规则，不增加未经批准的制度。输出带自动目录的 DOCX，并转换为 PDF；检查编号、
交叉引用、分页、页眉页脚和表格连续性。
```

验收重点：步骤可执行；角色和审批边界明确；目录、编号和版本信息正确。

## 案例 5：局部修改已有 Word

适合只更新指定章节、数据或图片，避免整份文档重新排版。

```text
使用 $aos-author-word，只修改文件中的“市场分析”“年度目标”和“行动计划”三节。
保留原始主题、样式、目录、页眉页脚、分节和页码。先复制源文件，再进行局部修改；
不要重建未涉及的章节。修改完成后输出差异摘要，清理评论、修订记录和个人元数据，
渲染全部页面检查分页变化。
```

验收重点：未指定内容没有变化；目录和页码更新；无评论或修订残留。

## 案例 6：PDF 公开发布检查

适合报告、白皮书、合同样稿和下载资料上网前的最终检查。

```text
使用 $aos-process-pdf，先不要修改文件。检查 PDF 的页数、页面尺寸、旋转、加密、
JavaScript、表单、链接、元数据和字体渲染；渲染全部页面，检查缺字、模糊、裁切、
重叠、异常空白页、错误页码和低清图片。按阻断发布、高优先级和建议优化输出清单。
我确认后再生成清理后的公开版本。
```

验收重点：结构检查和视觉检查同时完成；问题有页码、原因和建议动作。

## 案例 7：内部资料转公开版本

适合删除敏感数据、修订痕迹和个人元数据后对外发布。

```text
使用 $aos-publish-document，把内部报告转换为公开版本。建立删除清单，移除客户身份信息、
内部账号、密钥、未公开价格、评论、修订记录、作者和最近修改者元数据。不要简单遮盖文本；
应确认内容已从文档结构中删除。输出公开 DOCX 和 PDF，重新打开检查，并完成密钥扫描与
逐页视觉验收。
```

验收重点：敏感内容不是视觉隐藏；Office 包和 PDF 元数据均已检查；公开版可独立阅读。

## 案例 8：批量生成同版式项目报告

适合门店、客户、项目或产品的周期性批量报告。

```text
使用 $aos-publish-document，以已确认的参考报告为结构和视觉标准。读取数据目录，每个项目
生成一份独立 DOCX 和 PDF。保持章节、字号、间距、表格、页眉页脚和文件命名一致；只替换
该项目的数据、结论和图片。先生成一个样本，完成逐页验收并锁定规则，再批量生成剩余文件。
每份文件都要做页数、元数据和渲染检查，并输出汇总清单。
```

验收重点：先样本后批量；每份报告数据不串项目；失败项单独记录，不静默跳过。

## 案例 9：品牌视觉规范文档

适合 Logo、颜色、字体、摄影、包装和数字界面规则的集中管理。

```text
使用 $aos-publish-document，根据已授权的品牌资产制作品牌视觉规范。包含品牌理念、Logo
安全区和禁用方式、颜色、字体、版式、图形、摄影、包装、社交媒体和数字界面示例。
没有源文件支撑的应用图不要伪造为正式规范，应标记为建议示例。输出可编辑 DOCX 和高清
PDF，检查所有图片清晰度、颜色标注、图注和跨页一致性。
```

验收重点：规范与示例明确区分；资产授权清楚；图片和色值可用。

## 案例 10：长文档质量复核

适合已经完成但需要上线、印刷或归档的长报告。

```text
使用 $aos-process-pdf，对这份长文档进行最终质量复核。先生成低分辨率联系表检查整体节奏，
再以可读缩放逐页检查。核对章节起始页、目录页码、页眉页脚、空白页、表格跨页、图片清晰度、
字体替换、孤行和裁切。输出按页码排序的问题表，包含严重度、问题描述和建议修复方法。
```

验收重点：联系表只用于总览；最终结论来自逐页检查；所有阻断问题有定位信息。

## 常见错误写法

### 信息太少

```text
帮我做一个高级的白皮书。
```

问题：没有读者、资料、页数、输出格式和验收标准。

### 只要求生成，不要求验证

```text
把这些内容转成 PDF。
```

问题：转换成功不等于页面正确，应补充元数据、字体和逐页检查要求。

### 把模拟值当成事实

```text
缺少的数据你帮我补齐。
```

问题：公开文档必须区分事实、推断和模拟值。可以补结构，不能伪造企业事实。

## 推荐交付口径

在指令末尾加入：

```text
交付前必须重新打开最终文件，完成结构检查和逐页视觉检查。不要把测试文件、临时渲染图、
缓存、密钥、个人元数据或未获授权的资产放入最终交付目录。请报告输出路径、页数、验证结果
和仍需人工确认的事项。
```
